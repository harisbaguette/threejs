# 자기비평과 보완

## 첫 버전에 대한 판단

실사급 요청을 충족했다고 보기 어렵다. 젖은 바닥과 노을의 분위기는 있었지만, 창문은 그림을 붙인 판이었고 처마는 매끈한 면이었다. 선로와 풀도 단순한 도형의 반복이 드러났다. 밤은 같은 태양을 하얗게 바꾼 상태여서 시간대 표현도 부정확했다. 기능 테스트가 통과한 것을 시각 품질의 근거처럼 보고한 점도 부족했다.

## 고친 부분

| 문제 | 보완 | 확인 방법 |
|---|---|---|
| 차창의 깊이가 없고 차체가 막혀 있음 | 창문 위치에 실제 구멍을 만들고, 유리 뒤에 좌석·손잡이·운전대·천장등 배치 | 가까이 시점과 야간 렌더 |
| 매끈한 처마와 큰 빛 번짐 | 골이 있는 지붕, 받침 구조와 거친 재질, 낮춘 조명 강도 | 승강장 전후 캡처 |
| 단색 벤치와 평평한 선로 | CC0 목재·자갈의 색상·노멀·거칠기 맵, 색이 다른 자갈 인스턴스 | 재질 원본과 장면 비교 |
| 반사가 지나치게 균일함 | 바닥의 거칠기와 웅덩이 분포에 따라 반사 강도·선명도 변경 | 바닥 전경 |
| 밤에도 해가 보임 | 밤에는 태양과 수면의 태양 반사 제거, 객실과 역 조명 분리 | 밤 시점 |
| 풀의 직선 반복 | 휘어진 여러 잎을 가진 군락과 크기·색·방향 변화 | 선로 옆 근경 |
| 812×375에서 하단 조작이 화면 밖에 있음 | 고정 최소 높이 제거, 낮은 화면용 배치 | 320×568·375×812·768×1024·812×375 검사 |
| 카메라가 지면·처마·차체 내부에 들어갈 수 있음 | 입력 직후와 렌더 전에 카메라 위치 제한 | 단위 테스트와 방향키 50회 입력 |
| 정지 중에도 계속 장면을 그림 | 재생·카메라·조명 변화가 있을 때만 렌더 | 정지 1초 동안 실제 렌더 횟수 측정 |
| 정지 중 녹화하면 움직임 없는 영상이 됨 | 촬영 중 재생 후 이전 상태 복원 | 실제 영상 다운로드와 시간 진행 검증 |
| 화면 숨김 뒤 키보드 사용이 불편함 | 숨긴 조작은 `inert` 처리, 다음 화면 갱신 때 포커스 복귀 | H·Escape와 실제 포커스 대상 확인 |

## 디테일과 성능

객실과 유리를 추가한 중간 버전은 기본 화면에서 드로 콜이 356회에서 580회로 늘었고, 측정한 재생 프레임의 중앙값은 33.4ms였다. 이 회귀를 그대로 두지 않고, 같은 면의 유리창을 인스턴스로 묶고 식생을 공간별로 나눴다. 투명 유리의 면별 정렬은 유지하면서 불필요한 호출과 화면 밖 나무의 처리를 줄였다.

최종 측정과 검증 결과는 [QA.md](QA.md)에 기록한다. 측정은 이 컴퓨터의 Chrome 조건에 한정되며 실제 휴대폰 성능의 보증은 아니다.

## 남은 시각적 한계

나무의 수형과 먼 산에는 절차적으로 만든 3D 형태가 남아 있다. 건물·차량도 직접 구성한 모델이어서 실제 사진과 동등한 수준으로 평가하지 않는다. 이번 보완의 성과는 차창의 깊이, 표면 재질, 빛의 일관성, 구도와 사용성의 개선이다.

[실제 렌더의 수정 전후 비교](exports/review.html). 첫 버전과 수정한 코드를 각각 실행해 저장한 1440×900 이미지다. 구도 변경도 포함한다.
