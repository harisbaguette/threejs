데스크톱과 모바일 렌더를 직접 열어 확인했습니다. 모바일에서 전철 앞부분이 잘리던 구도를 별도로 조정했습니다. 창문은 운전실과 객실의 재질을 구분하고, 바다의 반복된 흰 줄무늬를 제거했습니다. 비는 처마 아래에서 숨기며, 빗방울이 높이 범위를 순환할 때 긴 선으로 늘어나지 않도록 양 끝점을 함께 이동시킵니다. 바퀴 접촉 높이를 레일 상단에 맞췄습니다.

샘플 `exports/shiosai-preview.mp4`는 H.264, 1600×1000, 30fps, 11.997초, 15,189,889바이트입니다. `ffprobe`로 확인했고 7초 지점의 프레임도 추출해 확인했습니다. PNG 사진 두 장도 같은 폴더에 있습니다.

렌더 통계의 한 표본은 프레임당 361개 드로 콜, 약 176만 삼각형입니다. 반사·그림자·후처리 등 여러 패스를 포함한 값입니다. 실제 휴대폰의 성능을 보장하는 수치가 아니며, 모바일 검사는 Chrome 화면 크기·터치 에뮬레이션으로 수행했습니다.

디자인 경고 6개는 HTML 메타 태그의 색상 값 1개와 로컬 SVG 아이콘의 출처 속성 5개입니다. 아이콘은 프로젝트에서 작성한 `public/icons.svg`를 사용합니다. Vite는 Three.js 청크가 500kB를 넘는다는 경고를 냅니다(압축 전 579kB, gzip 148kB). 빌드는 정상 완료됩니다.

첫 작품 `01-slow-rail`은 Git에 저장되어 있던 파일 22개와 바이트 단위로 같음을 확인했습니다. 이동 후 기존 단위 테스트 5개, 빌드, 데스크톱·모바일 브라우저 기능 검사를 모두 통과했습니다.

수정 파일의 import·HTML·소재 경로와 호출 측을 스캔하고, 반대 방향으로 반환값·UI 식별자·아이콘 심벌·소재 해시를 확인했습니다. 현재 두 작품의 폴더 경로, 실행 명령, 빌드와 저장 기능은 서로 일관됩니다.

검증 화면은 Git에서 제외된 `test-results/`에 있습니다. 영상 저장에는 소리가 포함되지 않습니다. 장면은 가상 역을 직접 모델링한 실시간 3D이며, 사진 측량 기반의 실사 복제는 아닙니다.
