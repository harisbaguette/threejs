## 실제 측정

| 항목 | 디테일 추가 직후 | 최적화 후 |
|---|---:|---:|
| 기본 화면 드로 콜 | 580 | 422 |
| 렌더 삼각형 수 | 2,439,023 | 1,952,725 |
| 재생 프레임 시간 중앙값 | 33.4ms | 16.7ms |
| 재생 프레임 시간 95백분위 | 50.1ms | 33.4ms |

같은 면의 유리창을 묶고 식생 인스턴스를 공간별로 나눠, 화면 밖의 식생까지 한 번에 그리던 비용을 줄였다. 초기 완성본의 프레임 중앙값은 16.7ms였다. 최종 보완본은 중앙값을 유지했지만 95백분위는 33.4ms다. 모든 상황에서 초기 버전보다 빠르다고 평가하지 않는다.

풍경과 카메라가 멈춘 뒤 약 1초를 측정한 추가 렌더 횟수는 **0회**다. 모션 감소 설정에서는 정지 상태로 시작한다. 촬영 중에는 재생한 뒤 이전 상태로 복귀한다.

## 발견한 문제의 근본 수정

카메라를 입력 직후에도 제한해 렌더 프레임 사이에 경계 밖 위치가 생기지 않도록 했다. 화면 숨김은 `opacity`와 `inert`가 담당한다. 중복된 `visibility` 전환이 포커스 복귀를 막는 것을 DOM 속성과 실제 focusin·focusout 이벤트로 재현했고, 이를 제거한 뒤 다음 화면 갱신에 포커스를 복귀시켜 검증했다.

9개 단위 테스트 외에 `npm run test:review`가 실제 Chrome에서 방향키를 50회 입력하고, 정지 중 녹화 파일을 저장하며, 네 가지 작은 화면의 모든 버튼을 검사한다. `test-results/review/baseline.json`과 `after.json`에 측정값, 같은 폴더에 전후·모바일·야간·카메라 경계 캡처가 있다. 이 폴더는 Git에서 제외한다.

재질·모듈의 import와 호출 측, 반환값·UI 식별자·에셋 해시를 대조했다. API 키·동적 코드 실행·사용자 데이터 전송은 추가하지 않았다. 작업 범위는 `02-shiosai`이며 다른 작품의 진행 중 변경은 보존한다.

Vite의 Three.js 청크 크기 경고는 남는다(580kB, gzip 149kB). 디자인 경고는 HTML 메타 색상, 로컬 아이콘 출처 속성, 비교 화면의 작은 보조 라벨이다. 모바일 검사는 화면 크기 에뮬레이션이며 실제 휴대폰의 발열·프레임 속도를 보증하지 않는다.

사진 두 장과 샘플 영상도 보완한 장면으로 갱신했다. 영상은 H.264, 1600×1000, 11.795초, 8,490,665바이트다. 실시간 녹화라 프레임 간격은 가변이고 이번 파일의 평균은 약 17.2fps다. `ffprobe`와 7초 지점의 디코딩 프레임으로 확인했다. 고정 30fps 영상으로 표기하지 않는다.
